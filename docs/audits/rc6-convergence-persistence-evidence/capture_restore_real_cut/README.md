# Scope of the preserved diagnostics

`DOSSIER.json` binds every original RAW byte stream and its lossless gzip copy
with both original and stored SHA256. Gzip uses mtime zero. The original files
remain in their original locations. Private DATA copies and large databases
are excluded; the source indices, profiler code, actual argv, preflights,
JUnit, custody inventories, stdout, partial progress and samples are retained.

The driver and product are different authorities. Driver `15b36374` ran 18
native guards and both initial phases. Driver `dc817b73` ran 21 guards and
the one NONE control. Driver `8d57319c` ran 34 guards for complete receipts and
default NONE. Each guard invocation used its whole 1706-file Git export;
product calls in the diagnostic children came from whole Product400, 1703
files, with no overlays. All used literal frozen311157, not the earlier
158-distribution environment.

The standalone restore returned the same original sequence-one PRE cut in
8.192 seconds, using 754880512 bytes peak RSS. It verified four role wires and
checkpoint semantics. This is separate from the original BIG90 failure, which
published its first cut at 83.830 seconds and exhausted its 90-second deadline
during the subsequent restart read.

The initial TIMED capture diagnostic terminated with SIGSEGV at 10.237 seconds.
The last recorded stage precedes the whole native report payload decoder. The
162-byte sample ends at a serialization filename and identifies no function
or line. It cannot locate the crash specifically in parsing, shape validation,
recanonicalization or cleanup. No report preparation or final native receipt
was recorded. The crash is preserved as unknown, not assigned to product or
sampling solely by timing coincidence.

The single NONE control had no sampler and an empty samples file. It completed
native report decoding and semantic/header checks, then entered preparation.
At 60.058 seconds the wrapper killed and reaped it for the unchanged independent
diagnostic watchdog. Its sampled peak was 1485451264 bytes. Preparation did not
return and its timers were not flushed before the kill. The decoded graph may
have different aliases from the original publisher graph; this run supplies
no publisher CPU claim, capture duration or optimized-publisher acceptance.

Its last complete timing snapshot has `_payload(report)` 26.521 wall/26.513 CPU
seconds. Inclusive subcomponents are `_loads` 14.431, `_shape` 4.586 and
recanonicalization 4.037 seconds. The 9.330-second unpack total includes three
calls: the prior wire check and the later report decode. Do not sum inclusive
timers or attribute that complete unpack total only to report decoding.

Original DATA full hashes and the selected eleven stat fields stayed identical
through every phase. Each private copy and Product400 file SHA/mode/blob set
also stayed identical. The NONE timeout has no final child receipt/import
closure; the wrapper's complete source/custody checks are retained independently.

The later Source-only complete-receipt guard addresses a distinct static
profiler gap: exit zero without a final native receipt could previously have
looked completed. Neither failed capture had exit zero. That gap did not cause
or replace either failure. The default NONE setting avoids auxiliary sampling
and does not establish the cause of the SIGSEGV.

Every item remains `diagnostic_only=true`, `acceptance_complete=false`. No
worker tick, new financial scenario, provider request, real route, artifact,
deployment, full runtime acceptance, horizon or nine-hour retention proof is
claimed. The original 0.25-second source-capture failure is not causally closed
by these report/restart diagnostics.
