## Added formats and exact RAW identity

Discovery remains within the pre-existing evidence directories. Python archival `.source` bytes are never imported, executed or treated as a native guard by this format extension.

Every added RAW encoding record retains compressed SHA256/bytes, uncompressed SHA256/bytes and actual gzip mtime when applicable. Identity source/text files retain both equal byte identities. Only named supported gzip member formats are decoded; arbitrary ZIP/TAR archives are unsupported. Gzip verifies a single complete stream, CRC, no concatenation/trailing bytes and a 32 MiB decoded bound. No directory, environment variable or command-line input can raise that bound.

`.json.gz` metadata keeps the complete original JSON value, including capture source/tree/environment/scope/counts, signed zero, nulls and literal ref-shaped data. Duplicate keys and nonfinite JSON constants reject decoding. DERIVED `raw-json-metadata` references include `json_encoding` plus the existing full source SHA/tree/blob/mode/SHA256/bytes binding and exact value hash. Legacy v2 plain `.json` refs without `json_encoding` remain accepted; that legacy shape cannot resolve a compressed JSON member.

The compact schema remains `rc6.remediation-register.v2` with a controlled additive ref encoding field. All original `E001`–`E210` objects and fields remain literal and unchanged; only added DERIVED copies and bindings are shared. Resolver expansion verifies RAW encoding and custody again from immutable Git before accepting the documentary reconstruction. Encoding/ref/member changes reject instead of granting execution authority.
